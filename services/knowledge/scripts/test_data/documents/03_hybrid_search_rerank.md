# 混合检索、RRF 与 Rerank

来源：Vault 的《混合检索》《全文检索》《RRF》《Rerank》（6_Databases/notes/）。本文整理概念，不将笔记流程图中的检索引擎配置视为项目事实。

## 两条召回路径

向量检索侧重语义相似性；全文检索侧重词级匹配。全文检索通常先分词，借助倒排索引找到包含查询词的候选，再进行相关性排序。倒排索引记录的是“词到包含它的文档列表”，不是逐篇扫描全部正文。

混合检索把向量路径和全文路径的候选结合起来，使语义匹配与关键词匹配互相补充。

## RRF 融合

RRF 是倒数排序融合。它关注每条路径里的排名，而不是直接相加 cosine 相似度与全文检索原始分数。名次越靠前，对融合结果的贡献越大。这样可以融合不同评分尺度的结果。

RRF 使用已有排名合并候选，不是把 query 与正文送入模型重新计算语义相关性。

## Rerank 联合编码

这里讨论的 Reranker 将 query 和 chunk 一起输入模型，对这一对内容计算相关性分数。query 与 chunk 联合参与判断，而向量检索通常先分别编码，再比较向量。

文档的独立向量可以预先计算，联合编码分数却依赖当前 query，不能提前为所有未来问题建立同样的分数索引。因此先召回少量候选，再做 Rerank，比对全库每个 chunk 做联合编码更合适。

一条典型流程是：向量召回与全文召回 → RRF 融合 → Rerank 精排 → 将选出的 chunks 交给 LLM 生成。融合与精排解决的问题不同，不能把 RRF 当成 Reranker。
