# RAG：召回、精排与生成

来源：Vault 的《RAG》《Rerank》（6_Databases/notes/）。本文为技术内容整理，不是当前项目运行配置。

## 三个阶段

RAG 可以按召回、精排、生成理解。召回阶段接收用户 query，从知识库中快速找出相关候选 chunks，重点是覆盖可能有用的依据，而不是直接写答案。混合检索可以同时利用向量和全文检索。

精排阶段接收 query 与候选 chunks，对候选重新判断相关性，挑选更适合交给 LLM 的少量片段。生成阶段才把 query 和选出的上下文一起交给 LLM，输出答案。

笔记用召回 top-20 到 top-50、精排保留 top-5 到 top-10 举例。这些是理解候选逐步缩减的示意数值，不是固定标准，也不是本项目的实际参数。

## 为什么分阶段

先用快的检索方式缩小范围，再用更精细的相关性判断筛选，可以避免对整个知识库逐条做昂贵的联合编码。召回输出候选，精排输出排序后的依据，生成输出自然语言答案，三者职责不同。
