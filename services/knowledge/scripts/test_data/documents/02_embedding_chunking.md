# 向量检索：Embedding 与分块

来源：Vault 的《向量检索》（6_Databases/notes/）。本文保留概念性内容，省略依赖具体实现的断言与经验比例。

## Embedding 与语义检索

Embedding 把文本映射成固定长度的浮点数向量，用向量空间中的接近程度表达语义相似性。向量检索把 query 编码后，与文档 chunks 的向量比较，再按相似度排序。它关注语义，而不只是文本是否出现同一个词。

文档向量可以预先生成并建立索引，查询时再生成 query 向量。不同 Embedding 模型的向量空间不能直接混用；切换模型时，需要用一致的模型重新编码文档和查询。

## 分块参数

chunk_size 控制每个 chunk 的长度上限，单位要看配置是字符还是 token。chunk_overlap 表示相邻片段预留的重叠区域，目的是降低关键信息跨越切分边界时被割裂的风险。不能把配置的 overlap 理解成任何切分结果都保证具有相同重叠长度。

## 分块策略

固定长度分块按长度切割。递归分块则按优先级尝试段落、换行等分隔符，尽量保留自然边界；遇到仍然过长的片段，继续使用更细的分隔符，并合并相邻小片段。

语义分块借助 Embedding 判断相邻句子的语义变化，在主题发生变化的位置切割。它需要额外的语义计算，因此存在成本和延迟开销。笔记重点提到的适用情况是文档结构较差，例如 OCR 纯文本缺少段落，或者一个段落混合多个主题。它不是无条件优于其他策略的默认选择。
